# Hotel Booking System with MongoDB


Благодаря разделению ответственности удалось интегрировать MongoDB без изменения бизнес-логики сервисов и API.

## Интеграция MongoDB

MongoDB была подключена как дополнительная база данных alongside PostgreSQL.

### Для MongoDB был реализован репозиторий:

HotelRepositoryMongo

Реализация MongoDB была выполнена только для сущности Hotel.

## Почему MongoDB была реализована только для Hotel

Сущность Hotel лучше всего подходит для document-oriented подхода MongoDB, потому что:

- структура отеля является гибкой;
- отель может содержать массивы тегов;
- возможны дополнительные динамические поля;
- отсутствует сложная реляционная зависимость.

MongoDB позволяет удобно хранить подобные данные в одном документе без необходимости нормализации.

## Почему остальные сущности остались в PostgreSQL

Сущности Booking и User

имеют более выраженные реляционные связи:

- Booking содержит ссылки на User и Hotel;
- необходим контроль связей;
- важна целостность данных.

Поэтому PostgreSQL лучше подходит для хранения транзакционных данных и связей между сущностями.

Таким образом проект использует hybrid architecture:

- PostgreSQL для relational data
- MongoDB для document data



## Embedded vs References
### Embedded documents

В коллекции hotels используется embedded подход для:

tags

Причины:

- данные принадлежат только отелю;
- данные используются вместе с отелем;
- нет необходимости хранить tags отдельно.

### References

Для Booking используется reference на Hotel через hotel_id.

Причины:

- бронирования являются отдельной сущностью;
- один отель может иметь множество бронирований;
- бронирования изменяются независимо от отеля.
- Реализованные CRUD операции


## Использовались типы данных:

- String

- ObjectId

## Docker инфраструктура

Проект запускается через Docker Compose.

Контейнеры:

- hotel-api
- hotel-db (PostgreSQL)
- hotel-mongo (MongoDB)

## Запуск проекта

docker compose build
docker compose up

Были реализованы:

- document-oriented model;
- CRUD операции;
- schema validation;
- работа с массивами MongoDB;
- Docker инфраструктура;

Работа показала различия между relational и document databases, а также преимущества MongoDB для хранения гибких структур данных.
